Jev as a fuzzy linter for coding agents

We tried the idea from the forwarded post: after every file edit, a hook sends the new code to TypeSafe's Jev model in one call and asks it about a list of small coding rules. Violations come back to the agent in two tiers, fix these and double-check these. We measured it on labeled test edits and on real Claude Code runs, in TypeScript and Swift.

Recommendation

Adopt it, as a non-blocking hint, with thresholds of 0.8 and 0.5 and a trimmed rule list. It is accurate, fast, nearly free and has never broken a run. But on real tasks it only nudged quality, because the agent already wrote mostly clean code. Treat it as a cheap guardrail, not a quality step-change.

What we built

A PostToolUse hook (src/hook.ts) that works in Claude Code and Codex. It reads the edit event, pulls out only the code the edit added, and sends it to Jev with one yes/no question per rule. Jev answers each with a probability, called a Noul. The hook then tells the agent:

  • p ≥ 0.8: "Likely violations — fix these"
  • 0.5 ≤ p < 0.8: "Possible violations — double-check; ignore if the code is actually fine"

Anything below 0.5 is dropped. The findings go back as extra context, so they never block the agent. If Jev is slow or down, the hook stays silent.

Following the post, we kept only rules Jev can judge from the snippet alone, with no other files needed: 13 for TypeScript and 13 for Swift. Examples: no any, no force-unwraps, no empty catch, no leftover debug prints, no bare TODOs, no comments that just restate the code, no vague names, no magic numbers. Each rule spells out what counts and what doesn't, in rules/*.json.

We compared three judges on the same edits:

  • Jev, one call per edit.
  • GPT-5.4-mini, a fast general LLM given the same rule text and asked yes / maybe / no per rule.
  • Regex, for the 7 rules per language a pattern can express. This is roughly what a classic linter gives you.

What we learned

  • The medium tier works, and 0.5 is the floor. Of Jev's findings between 0.5 and 0.8, 24 of 28 (86%) were real violations. Including them lifted TypeScript held-out recall from 84% to 98% and added no false alarms. Below 0.5 it turns into noise: 6 of 15 real between 0.3 and 0.5, and 1 of 24 between 0.2 and 0.3. This supports the post's claim that the second tier greatly increases catches for little noise.
  • Jev beat the general LLM on noise, speed and cost. GPT-5.4-mini flagged 21% of clean TypeScript edits and 8% of clean Swift edits. It was mostly over-strict on magic numbers, for example numbers inside JSON test fixtures or 200..<300. It was also about 4× slower (1.05 s median) and cost about 23× more ($17.86 per 10,000 edits).
  • It is stable. Across three repeated runs, no rule probability moved by more than {{CONS_MAX}} (99th percentile {{CONS_P99}}).
  • Shape and size don't matter. Precision and recall were 98–100% for every payload shape, Codex apply_patch included. The 12 edits over 80 lines had 17 of 17 violations found and 1 false flag.
  • Where it's weak. Rules that need counting or tracing: ts-no-deep-nesting (70% recall at 0.5, 20% at 0.8) and ts-no-floating-promise (75%, missing async calls inside useEffect). TypeSafe's own docs list counting and indirection as known weak spots.

A note on thresholds: 0.8 and 0.5 were set before any data came in. An automatic tuner on the tuning split picked 0.7 and 0.25, from very few examples. On held-out data that tuned choice raised clean-edit false alarms to 4–8%, so we kept 0.8 / 0.5.

Experiment 2 · Real agent runs

Setup. Claude Code (Sonnet, headless) did 12 realistic tasks, 6 per language. Examples: a GitHub client with pagination, a token-bucket rate limiter, a SwiftUI list with a URLSession view model, an image-loader actor. Each task ran twice under each of three conditions: no hook, Jev with both tiers, and Jev with the high tier only. That makes 72 runs, interleaved so any drift in the model hits all three conditions equally. User hooks, plugins and MCP servers were switched off. GPT-5.5 then graded every final file against the same rules. It did not know which condition produced the file.

What happened inside the runs

  • The agent takes the feedback. It fixed 19 of 20 high-tier findings, usually in its very next edit, and resolved 8 of 10 medium-tier ones. It didn't argue with the hook or mention it to the user.
  • Mechanical rules went to near zero. Swift force-unwraps dropped from 6 to 1, TypeScript non-null assertions from 3 to 0, and empty catches from 1 to 0.
  • The overall effect is small and not proven. Violations fell by about 0.5 per task, but the 95% intervals include zero. Sonnet already wrote fairly clean code (2.3 violations per ~125 lines), and most of what was left are judgment calls on names and numbers.
  • High-only did as well as both tiers here. It was also cheaper: +7% agent cost and +8 s per task, compared with +15% and +22 s for both tiers. With 24 runs per condition, we can't tell the two apart.
  • Reliability. {{HOOK_CALLS}} hook calls, {{HOOK_ERRS}} errors, about 280 ms each. Every run built.

Jev vs the grader on real code

We also ran Jev over the final agent-written files and compared its verdicts with GPT-5.5's. The two agree on mechanical rules. They split on names and numbers:

{{AGREE_ROWS}}
RuleBoth flagOnly JevOnly grader

Most "only grader" cases are the rule text being read literally:

  • let (data, response) = try await … fails because data is on the banned-name list.
  • options.heartbeatIntervalMs ?? 30000 counts as a magic number, even though the parameter name explains it.

Jev is more lenient there, which is arguably closer to what a reviewer wants. The "only Jev" empty-catch cases were catch { return; } blocks that do silently drop the error. The one clear Jev miss on real code is nesting depth: four-level CSV-parser loops were scored 0.22–0.37.

Recommendation

  1. Turn it on as a hint, not a block. Use additionalContext mode with thresholds 0.8 and 0.5. Keep both tiers: the labeled data supports them strongly, and the real-run difference is too small to measure. Switch to high-only (JEV_LINT_TIERS=high) if the extra ~14 s per task matters.
  2. Pin the model. Set JEV_LINT_MODEL=jev-1.13.0, so an update to jev-latest can't silently shift the thresholds. Re-run bun eval/run.ts before moving to a new version.
  3. Fix the rule list before rolling out widely.
    • Drop ts-no-deep-nesting and use ESLint max-depth or SwiftLint nesting instead.
    • Move ts-no-floating-promise to typescript-eslint's no-floating-promises where type-aware lint exists.
    • Rewrite *-no-vague-names to decide whether data from a network call is acceptable.
    • Rewrite *-no-magic-numbers to allow named default parameter values.
    Right now those two rules produce most of the disagreement.
  4. Keep real linters where they exist. Regex-level rules (any, !, try!, as!, console.log) are free and exact in Biome, ESLint or SwiftLint. Jev's added value is the judgment rules (restating comments, commented-out code, secrets, UI updates off the main thread) and zero setup in any repo.
  5. Expect the most benefit where agents are sloppier. That means smaller or faster models, long sessions, or larger rule sets. That's the next thing to measure.

What we don't know yet

  • Codex end to end. The Codex CLI on this machine is broken: the npm package is missing its platform binary, and the desktop app isn't installed. So Codex was only tested through its apply_patch payloads (79 labeled edits, 98% precision and recall). The Claude side was tested end to end.
  • Synthetic labels. The labeled edits were written and labeled by Claude subagents, one annotator per edit. The tuning set turned out easy (Jev near 100%), and real code is fuzzier, as the grader comparison shows.
  • Small end-to-end sample. One agent model (Sonnet), 12 tasks, 2 repeats. We'd need roughly 5× more runs to detect a 0.5-violation effect reliably.
  • The grader is an LLM. GPT-5.5 applies the rules very literally. We spot-checked its disagreements with Jev, but did not hand-label the real files.

How to run it

# install (repo: ~/Repos/jev-lint)
bun install
security add-generic-password -a "$USER" -s typesafe-api-key -w   # or TYPESAFE_API_KEY

# Claude Code: ~/.claude/settings.json → hooks.PostToolUse
{ "matcher": "Write|Edit|MultiEdit",
  "hooks": [{ "type": "command", "command": "JEV_LINT_MODEL=jev-1.13.0 bun ~/Repos/jev-lint/src/hook.ts", "timeout": 15 }] }

# Codex: ~/.codex/hooks.json → hooks.PostToolUse
{ "matcher": "Edit|Write|apply_patch", "hooks": [ …same command… ] }

# re-run the evals
bun eval/run.ts --runs 3        # labeled edits: Jev vs GPT-5.4-mini vs regex
bun eval/e2e/run.ts --reps 2    # real Claude Code runs with / without the hook
bun eval/e2e/grade.ts           # blind grading
