Evidence you can inspect.

The demo shows a test that passes without proving its named behavior. The experiment measures what reaches code review when JevLint is on versus off.

JevLint checks edits against your team’s rules and sends findings back to the coding agent. Checks are probabilistic hints, not guarantees of correctness. Tests, type checking and code review still matter.

What “41% fewer” means

41% fewer

Review findings covered by JevLint’s rules, in a 48-run experiment.

Twelve synthetic React and SwiftUI tasks ran twice in each condition: 24 Claude Code runs with the hook off, and 24 with JevLint’s asynchronous background hook on. All five packs were enabled, with 170 rules at the time. This historical experiment used TypeSafe Jev; it is not a Cloudflare Clef or OpenAI Decisions API comparison.

The relative reduction is (32 − 19) / 32 = 40.625%, rounded to 41%. A finding counts when it maps to a supported rule. This does not count review rounds, unique reviewers or all review comments. All reviewer findings fell 6%.

How it was reviewed

An independent blind AI reviewer reviewed the final code without being told the lint rules. A separate AI mapping step assigned each finding to a rule or to “none.” The reviewer and mapper used GPT-6-Luna with low reasoning effort.

Differences were paired by task and repetition. The mean change was −0.541667 rule-covered findings per run; the report’s 95% bootstrap interval was −1.083333 to −0.041667. The calculation uses 5,000 resamples with seed 0 and task/repetition pairs, rather than task-clustered resampling. Nine pairs improved, five worsened and ten tied.

The interval narrowly excludes zero. This is a small synthetic React/SwiftUI cohort, with AI review and AI rule mapping. It does not establish the same effect for every repository, language, provider or human review process.

What it does not measure

No measured savings in review cycles, development time, tokens or overall cost are claimed. The notebook’s separate review-and-fix experiment did not save a fix round. In this all-packs on/off cohort, mean agent cost rose from approximately $0.1356 to $0.1800 per task, and wall time rose from 51.6 to 58.6 seconds.

Moving rule feedback earlier may change where a fix happens. The workflow animation illustrates that idea while retaining review; it does not show a measured reduction in rounds or imply that re-review disappears.

What the code demo shows

The animated code adapts the public evaluation case tsp4-dev-006. Its test calls real code, then compares the result with itself and asserts true equals true. The saved TypeSafe Jev evaluation scored rule ts-test-cannot-fail at 0.97. “This test proves nothing” is an editorial headline, not a verbatim provider response.

prorate(plan) abbreviates the original call. This is a walkthrough of a saved result, not fresh live inference. The historical cache does not preserve an exact returned model version or execution timestamp, and the complete historical pack prompt cannot be reconstructed.

The stronger expect(credit).toBe(10) assertion was checked locally with Bun against deliberately broken synthetic proration code: the old tautology passed, the stronger assertion failed, and correcting the synthetic calculation made it pass. The correction was not re-scored by Jev. No clean provider verdict is shown, and the finding is not attributed to Decisions or Clef.
